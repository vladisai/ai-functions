## Learning

Learning is the process of *improving a skill through experience*. At least, that is a dictionary definition of learning. In machine learning “experience” is past data, or more precisely *instantiated* data, and a “skill” is the *inference function* that maps future data onto decisions or actions.[^1] More precisely, the inference function instantiates future data into commands (*e.g.*, API calls) or signals that are fed to an actuator or decoder to produce a decision or action. Thus, in machine learning the purpose of learning is to *leverage past data to improve future inference.* Since the goal of learning is to improve inference, we start from there.

## Reward and loss

We will be concerned with two distinct forms of inference: One where the effect of the decision or action to be inferred is known during the inference process, and one where the effect becomes manifest only *post-mortem*, that is, after the decision has been made or the action has been taken. If no effect is ever manifest, learning cannot take place. Such an effect is usually in the form of a reward or loss function, which for every decision or action returns a number which could be positive (reward) or negative (loss); when the loss or reward can only take two values, *e.g.*, $\{0, 1\}$, we refer to it as a *verifier*. For simplicity we refer to the effect of the outcome of inference as a *loss*, which may be negative (reward) or binary (verifier). We also refer to the outcome of inference as *decision*, which could be the issuing of a command that triggers an action.

## Inductive vs. transductive inference

When the loss function is available during the inference process, one can simply search over the entire set of possible outcomes (decisions or actions) for the one(s) that minimize the loss. This may be done analytically if the expression of the loss function is known, or empirically if the loss function can be evaluated on any possible outcome of inference. We call this form of inference *transduction.* If the loss function or its value is not known, the inference process is blind; the inference function therefore can only be based on experience (*e.g.*, an instantiated training set) that is disjoint from the present (test) datum. The quality of inference therefore depends crucially on the relation between past data – used to craft the inference function – and future data, on which the inference function eventually operates. This process is called *induction*. Inductive inference always involves some kind of assumption, often implicit in the subjective choice of prior, bias, regularizer, or hypothesis underlying the design of the learning process. Such “inductive hypothesis” or “inductive bias” is necessary for inductive inference, and is always present even if not always explicit.

## Statistical learning

Classical machine learning teaches induction: Given a dataset comprised of data never to be seen again (the “training set” $D$), infer the parameters (“weights” $w$) of a function $f_w$ to be used for inference on “test” data $x$ never seen before, producing an outcome (decision, or action $y$) typically chosen among a finite set of *hypotheses*.[^2] Inductive inference involves uncertainty, since we cannot know the outcome of inference until after the decision has been rendered. It is typical to assume that the training set of past data $D$, comprised of $N$ sample inputs $x_i$ (data) and corresponding outputs (decisions or actions $y_i$), is drawn from some (unknown) distribution $P$, $(x_i, y_i) \sim P$ with $i = 1, \dots, N$. Then, as long as future data $x\sim P$ is also drawn from the same distribution $P$, it is possible to characterize ensemble properties of the outcome of future inference and guarantee that the loss is bounded. This leads to the notion of *generalization*.

## Generalization

Generalization is the property of past solutions to apply to future problems. More precisely, a model generalizes if the expected loss incurred on future data is small, typically as measured in relation to the average loss incurred on past data, which is the training error. The difference between the two is known as *generalization gap*. *Uniform generalization bounds* are expressions that bound the generalization gap in a way that is *independent of the particular distribution $P$* from which the data is drawn. In their most general form, if we indicate with $\ell(x,y)$ the loss in rendering hypothesis $y$ in response to input $x$, uniform generalization bounds claim that, for any $P$, we have

$$
{\mathbb E}_P \ell(x,f_w(x)) \le \underbrace{\frac{1}{N} \sum_{(x_i, y_i) \in D} \ell(x_i,y_i)}_{L(w;D)} + \beta \underbrace{I_P(w; D)}_{R_D(w)}.
$$

That is, the expected error on future data $x$ obtained by rendering an hypothesis $y = f_w(x)$ (left-hand side) – which obviously we cannot compute since we do not know $P$, but that we would nevertheless like to make small – is bounded by the training loss $L(w;D)$, which is entirely under our control and minimized over $w$ as part of the training process, and a regularization term $R$, which measures the “information” that the trained parameters $w$ share with the dataset $D$. In a sense, this bound states that past performance $L$ guarantees future rewards (left-hand side) so long as we reduce complexity, as measured by the regularizer $R$. We could make the training loss zero by storing the dataset $D$ into the weights $w$ (“overfitting”), but the complexity cost would be high because we have to store the entire dataset into the weights. Conversely, we can make the complexity zero by choosing zero weights, or a constant inference function $f_w$, but then we would pay a price in the loss. But if we manage to trade off the two, then the resulting trained model $f_w$ *generalizes* in the sense that the function that worked on past data will also work on future data. If this sounds suspicious, it is.

## The problem with induction

First, the assumption that future data will be drawn from the same distribution of past data is at best unverifiable, since future data is not instantiated. But arguably it is unfalsifiable, since one can at best test that hypothesis empirically on a held-out dataset, which of course depends on the choice of dataset. But even more fundamentally, paraphrasing De Finetti, there is no distribution $P$ to begin with. The finite dataset $D$ could have been drawn with identical likelihood from infinitely many distributions. Even if there was a “true” one, future data would have no way to know which. Probability does not exist in the sense that it is an abstract concept that we concoct to be able to predict ensemble properties of data, but while using probability to describe future data makes sense, instantiated data $D$ is objective and in our possession, so we should not have to make *any* assumption about it.

To better see the problems with the notion of generalization, just notice that uniform generalization bounds have the unknown distribution $P$ in both the left and right-hand sides. Therefore, even if $P$ can be anything *it has to be the same $P$* in the past and forever after. That may be a sound assumption to make when playing cards, or dice, but it is fallacious when dealing with real data in business, finance, climate, language, and society. Such an assumption of *stationarity* of the underlying distribution is generally false, which forces practitioners of machine learning to resort to various ad-hoc fixes to deal with “out-of-distribution” behavior, or covariate shift, all solutions to self-inflicted problems since there is no distribution to begin with.

If induction is so problematic, why do we routinely apply it? In the 1700s, David Hume was interested in understanding the *reason*, or rationale, behind induction. He concluded that, if there was one, it would imply that future data must resemble past data and nature is a stationary process:

> *“if Reason determin’d us, it would proceed upon that principle that instances, of which we have had no experience, must resemble those, of which we have had experience, and that the course of nature continues always uniformly the same.”*

Since this is patently not the case, there is no rationale, or “logic,” behind induction. What is the alternative?

## Uncertainty vs. time

In transductive inference, there is no uncertainty involved since we can monitor the quality of the inference process along the way. Since usually the set of possible decisions or actions is countable if not finite, in the worst case one can brute-force search for the optimal outcome of inference. The only question in transductive inference is *how much time* it will take to find a decision or action that optimizes the loss. Note that not just the outcome of inference (the value of the decision or action) but the inference function itself depends on the test datum.

## Optimal Transductive Inference (Solomonoff Induction)

In 1964 Solomonoff set out to overcome the problem of induction by seeking an inference procedure that would be optimal not just with respect to queries (test data) that are drawn from the same distribution of training data (which does not exist in the first place). Rather, he sought a *universal algorithm* that is optimal for inference on *any* data, drawn from any distribution. This can be interpreted as the ultimate Bayesian inference algorithm, where averaging is done with respect to all distributions according to the universal prior (that assigns probability to data proportionally to the exponential of the shortest program length that generated them), or – more appropriately – as optimal transductive inference. The algorithm is deceptively simple: Take all the data that was ever observed (there is no distinction between training and test data), then execute all programs through a (universal) Turing machine, which are infinitely many but countable, and keep the programs that generate all observed data bit-by-bit. Finally, execute one more step of those programs, and average them according to their universal prior, the (negative) exponential of their length. This is universally optimal regardless of the distribution from which test data is drawn, which could be completely unrelated to the distribution(s) from which training data was drawn. The only issue is that the procedure could literally take forever, since some programs may not terminate.

## Levin's Universal Search

In 1972, in the same 3-page paper that introduced the notion of NP-Completeness, Levin introduced an algorithm that performs universal inference universally fast, meaning that no other algorithm can do better across all possible programs. It consists of a dovetailed search, which can be shown to take no worse than a constant factor longer than the optimal bespoke algorithm for a particular task. The problem here is that the constant, which depends on the task but not the instance, is the exponential of the length of the shortest optimal bespoke algorithm. This can be astronomical.

For this reason, both Solomonoff Induction (an unfortunate name) and Levin Search have been mere theoretical curiosities with no impact in machine learning or inference.

## Solomonoff's 1984 observation: The role of learning in optimal inference for verifiable tasks

In an obscure 1984 paper, Solomonoff pointed out that the only role that learning can play in optimal inference for verifiable tasks is to reduce the constant in Levin's search. In particular, if one has solved many tasks before, they can more rapidly sample or compose past solutions into a solution to a new (unforeseen) task. This reduces the time it takes to solve new tasks exponentially. This is the role of learning: *accumulate algorithmic information* (unlike statistical learning that advocates shedding statistical information) so one can achieve *generality* (literally, universality) rather than *generalization*.

## LLMs as Maximalistic Models of Computation

The problem with Solomonoff's 1984 program is that executing it requires having a distribution over programs that, if executed by a Universal Turing Machine, can solve the task at hand. This object was as out of reach in 1984 as it is today. However, a modern code model does provide a distribution of programs given a prompt which describes a task. Thus, it seems that LLMs could realize Solomonoff's program, except that they are not computers in the ordinary sense, as there is no “program” to speak of. A computer is a dynamical system that evolves from an initial condition that specifies a task to a final state that outputs a solution. Turing Machines are universal models of computation (they can compute any computable function, according to the almost-tautological definition of computability that Turing provided) designed to be *deterministic* and *minimalistic*, so we (humans) can better understand questions of computability and computation.

Conversely, LLMs are maximalistic (the bigger the better) and stochastic. They are literally first-order random walks where the trained backbone provides the drift vector field. A stochastic dynamical system cannot be controlled with a set of instructions provided as initial conditions (*i.e.*, a program). An initial condition can at most *condition* the execution of a stochastic computer, but can never *control* it. If the prompt is not a program (it specifies what the problem is, not how to solve it), and the weights are not a program (they are constant) and the chain-of-thought is not a program (does not even exist before execution starts), then what is the program? What is the language to control LLMs? What plays the role of *program length* as a key measure of complexity in Turing Machines?

It turns out, there is a precise sense in which LLMs are universal computers. This is not the trivial sense in which their weights can be tweaked to implement this or that Turing Machine. A pocket calculator with memory is Turing complete, but this is not the point of LLMs. The point of LLMs is that they are universal computers but largely antithetical to Turing Machines. In order to be controlled, they have to be treated for what they are: Stochastic dynamical systems.

## The New Solomonoff Program

Once understood that LLMs are universal computers that are stochastic and maximalistic, we can try to resurrect Solomonoff's program, and in particular the key result that the role of learning is to reduce the time it takes to solve unforeseen tasks. Improvement of a skill arises from reducing time, instead of or in addition to reducing uncertainty. And generality (*not* generalization) arises from universal inference through variable-length computation. This is the basis of agentic learning. Agentic learning allows improving any task, not just the task the model is trained on. This is fundamentally different from inductive learning, where the set of hypotheses (outcomes of inference) is fixed at the outset. In inference from agentic learning, one can test any hypothesis or solve any task regardless of whether it was observed during training. The benefit of experience is in helping solve new tasks faster.

The core engine to perform agentic learning is an LLM understood as a stochastic dynamical system capable of universal computation, and the key is how to learn (improve performance) and how to control it.

[^1]: In today's AI jargon, the term “skill” has come to denote a markdown file with instructions fed to a large language model as initial conditions. These can at most *condition* an existing inference function to produce the decisions or actions we wish, but do not alone embody any skill. Calling a skill a set of prompts would be akin to claiming to be able to play the violin by telling ourselves “you are a world-class violinist; you play with passion and precision ...”.

[^2]: Note that the set of hypotheses consists of all possible outcomes of the inference process. Since learning is the process of inferring the weights $w$, or more in general the function $f_w$, it is common in inductive learning to refer to the inference function $f_w$ as an hypothesis. Since our framework is inference-centric, not inductive-learning-centric, we reserve the term hypothesis for the more general set of possible outcomes of inference, not just for the weights and not just for the process of training on a dataset of past data.
